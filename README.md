# AIWerewolf 本地部署版 MVP

这是完整项目源码，在你自己的电脑上运行。技术栈为 **React + Vite + Node.js + SQLite**，不使用 Sites、Cloudflare、D1 或其他托管平台。数据库和全部对局记录保存在本机。

## 1. 启动

先安装 **Node.js 24 或更高版本**（自带 npm），解压源码 ZIP，在 `werewolfdemo-local` 文件夹打开终端，执行：

```bash
npm install
npm run build
npm start
```

浏览器打开 **http://127.0.0.1:3000**。

数据库首次启动时自动创建，无需另装 SQLite、配置云账号或执行数据库迁移。停止程序按 `Ctrl+C`。之后再次启动只需 `npm start`；修改代码后重新运行 `npm run build`。

开发时运行 `npm run dev`，同样访问 http://127.0.0.1:3000，前端支持热更新。

> 本项目使用 Node 自带的 `node:sqlite`，Node 版本必须符合要求。部分版本会显示 SQLite ExperimentalWarning，这条提示不影响运行。

## 2. 如何使用

1. 首页选择「演示模式」，点击开始，无需 API Key 即可完整跑通一局。
2. 「真实模型」可配置 DeepSeek、千问、OpenAI 或其他兼容 Chat Completions 的 API，填写 Base URL、模型名、温度、API Key。
3. 对局页自动推进夜晚、发言、讨论、投票、死亡技能和胜负判断。支持暂停和单步。
4. 公共视角只显示公开信息；上帝视角可见所有身份、狼队、夜间行动、玩家判断、模型实际输入输出。
5. 点击导出保存 JSON。上帝视角导出完整记录；公共视角只导出公开内容。

真实模式会实际调用你配置的模型，不会自动切换成演示模式。全部玩家和主持人使用同一模型，但每次请求各自构造独立上下文。API 费用由你的模型服务商收取。

API Key 仅保留在当前浏览器标签页的会话存储中；请求发送给本机 Node 服务，再由本机服务发送到配置的模型地址。Key 不写入 SQLite 或对局 JSON。关闭标签页后若 Key 丢失，重新填写即可继续。支持 HTTP 或 HTTPS Base URL；无认证的本地兼容模型可在 Key 栏填写 `local`。

**保持对局页打开才会自动推进。** 离开页面后不继续后台运行，当前请求可能完成；再次进入点击「自动继续」。暂停会等待当前步骤完成。服务端重启后，已保存的对局仍可继续。

## 3. 文件与数据

```text
src/                    React 界面：创建、公共观察、上帝视角
server/index.ts         本地 HTTP 服务、开发与生产启动
server/api.ts           游戏 API
server/repository.ts    本地 SQLite 存储、自动建表
lib/werewolf/engine.ts  固定阶段流程、GM 和玩家请求、信息分发
lib/werewolf/rules.ts   固定板型结算函数
lib/werewolf/provider.ts 真实 API 与离线演示 Provider
tests/                 规则、信息隔离及本地完整对局测试
docs/                  用户提供的原始需求和规则
data/werewolf.sqlite    首次启动生成的数据库
dist/                  npm run build 生成的前端
```

备份时先停止程序，再复制整个 `data` 文件夹。源码包不包含数据库、API Key、依赖目录或构建产物。

默认仅监听本机 `127.0.0.1`，无登录或在线房间系统。可用环境变量 `PORT` 改端口、`DATABASE_PATH` 改数据库路径。正常本机使用无需设置任何环境变量。

## 4. 规则与最小约定

- 固定 12 人：普通狼 ×3、狼王 ×1、预言家/女巫/猎人/守卫各 ×1、平民 ×4。
- 狼人屠神或屠民任一胜利；全部狼人出局则好人胜利，不按双方人数相等判胜。
- 夜晚依次狼人、守卫、女巫、预言家，最后统一结算；将死玩家仍完成当夜行动。
- 守卫可自守、不可连守，可空守；女巫首夜不可自救，同守同救仍死。
- 毒刀重合按毒杀；毒杀和其他技能死亡不能触发枪；最后神职猎人、最后狼人狼王不能发动技能。
- 未明确的细节固定为：不开警长；自由讨论一轮；女巫每夜最多一瓶药；无解药时不再告知刀口；平票只对候选人重投一次，再平票无人放逐；存活玩家不投自己，不弃票。
- 狼队逐人提出刀口，票多者优先、同票取最小座位号；普通狼可自刀，狼王不选自己。

GM 掌握全局，每阶段通过模型给出阶段指令、行动顺序、死亡/放逐/胜负判断，服务端用少量固定规则校验并执行。公开播报来自结构化结果；GM 的全知解释只保存在上帝视角。普通玩家只收到自己的身份、观察、判断摘要和公开历史；狼玩家额外收到狼队关系。没有共享玩家上下文。

## 5. 验证

```bash
npm test
npm run build
npm run test:e2e
```

`npm test` 检查固定板型、屠边、同守同救、毒刀重合、猎人/狼王限制、首夜自救限制、连守、自查、信息隔离、平票，以及三组配牌的完整对局。

`npm run test:e2e` 会启动真实的本地 HTTP 服务，使用临时 SQLite 文件跑完整演示对局，验证 JSON 导出和信息隔离，并重启服务确认记录仍存在。它会自动清理临时数据库，不碰你的 `data`。

真实服务商的模型调用需要你提供 Key 后验证；演示使用明确标识的离线 Provider，不代表大模型策略水平。

## 6. 简单 API

- `POST /api/games`：创建，最小演示请求为 `{"mode":"demo"}`。
- `GET /api/games`：最近 50 局。
- `GET /api/games/:id`：公共信息。
- `GET /api/games/:id?view=god`：完整状态和事件。
- `GET /api/games/:id?view=god&logs=1`：包含模型请求和响应。
- `GET /api/games/:id?view=god&download=1`：下载完整 JSON。
- `POST /api/games/:id/step`：推进一个 GM 或玩家步骤，真实模式请求体为 `{"apiKey":"你的Key"}`。

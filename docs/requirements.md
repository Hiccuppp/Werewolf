# AIWerewolf 简化版需求文档

版本：MVP

目标：

构建一个最小可运行的 AI 狼人杀 Web 版本。

核心目标不是完整狼人杀游戏平台，而是验证：

-   大模型是否可以作为狼人杀主持人（GM）
-   多个大模型玩家是否可以自动完成一局狼人杀
-   是否可以保存完整对局记录
-   是否为后续 AI 推理分析提供基础

------------------------------------------------------------------------

# 一、范围

## 游戏规则

固定使用：

预女猎守狼王 12 人板。

角色：

狼人：

-   普通狼人 ×3
-   狼王 ×1

好人：

神职：

-   预言家 ×1
-   女巫 ×1
-   猎人 ×1
-   守卫 ×1

平民：

-   平民 ×4

胜利：

狼人：

-   屠神
-   屠民

任一满足狼人胜利。

好人：

-   所有狼人死亡。

------------------------------------------------------------------------

# 二、核心架构

简化版不实现复杂规则引擎。

采用：

    Web
     |
    Game Server
     |
    LLM Host Agent
     |
    LLM Player Agents

------------------------------------------------------------------------

# 三、主持人 Agent

一个 LLM 作为狼人杀主持人。

职责：

## 游戏流程控制

负责：

-   夜晚开始
-   唤醒角色
-   收集行动
-   结算结果
-   白天公布信息
-   控制发言顺序
-   发起投票
-   判断胜负

## 信息管理

主持人保存：

完整游戏状态：

-   所有人身份
-   存活状态
-   夜晚行动
-   技能状态
-   投票记录

向不同玩家发送不同信息。

------------------------------------------------------------------------

# 四、玩家 Agent

每个玩家一个独立 Agent。

每个 Agent 拥有：

-   身份
-   阵营
-   可见信息
-   历史公开发言
-   自己的判断

禁止：

玩家读取完整游戏状态。

------------------------------------------------------------------------

# 五、AI 玩家流程

## 夜晚

例如：

狼人：

收到：

    你是狼人。
    请选择今晚击杀目标。

返回：

    kill: player3

预言家：

返回：

    check: player7

女巫：

返回：

    save / poison / none

守卫：

返回：

    guard: player5

------------------------------------------------------------------------

## 白天

流程：

主持人公布死亡。

然后：

玩家依次发言。

发言内容：

自然语言。

例如：

    我认为7号昨天的发言有明显保身份倾向。

然后：

自由讨论。

最后：

投票。

------------------------------------------------------------------------

# 六、LLM 调用设计

第一版允许：

所有玩家使用同一个模型。

但是：

每个玩家独立上下文。

不要：

12个玩家共享一个上下文。

结构：

    Player Agent A
      |
      |--自己的身份
      |--公开历史
      |--自己的记忆


    Player Agent B
      |
      |--自己的身份
      |--公开历史
      |--自己的记忆

主持人单独保存全局状态。

------------------------------------------------------------------------

# 七、数据存储

保存：

## Game

-   gameId
-   创建时间
-   模型配置
-   胜利结果

## Events

保存：

-   夜晚行动
-   发言
-   投票
-   死亡
-   技能发动
-   阶段变化

## Player Logs

保存：

-   玩家看到的信息
-   玩家输出
-   模型配置

------------------------------------------------------------------------

# 八、Web 页面

只需要三个页面。

## 1. 创建游戏

配置：

-   模型 API
-   模型名称
-   温度参数

点击开始。

------------------------------------------------------------------------

## 2. 游戏观察页

显示：

-   当前阶段
-   玩家列表
-   发言记录
-   投票
-   死亡

支持：

公共视角。

------------------------------------------------------------------------

## 3. 上帝视角页

显示：

-   所有身份
-   狼队关系
-   夜晚行动
-   玩家最终判断

------------------------------------------------------------------------

# 九、技术方案

推荐：

Frontend:

-   React
-   Vite

Backend:

-   Node.js
-   TypeScript

Storage:

-   SQLite

LLM:

统一接口：

``` ts
interface LLMProvider {

chat(messages): Promise<string>

}
```

支持：

-   DeepSeek
-   千问
-   OpenAI
-   其他 API

------------------------------------------------------------------------

# 十、不做

第一版不要实现：

-   复杂规则引擎
-   多板型
-   真人语音输入
-   Observer Agent
-   复杂 UI
-   在线房间
-   用户系统
-   经济系统

------------------------------------------------------------------------

# 十一、完成标准

完成后：

用户可以：

1.  打开网页。
2.  创建一局预女猎守狼王。
3.  12个AI自动游戏。
4.  主持人自动推进。
5.  玩家自动发言。
6.  自动投票。
7.  自动结束。
8.  查看完整记录。
9.  查看上帝视角。

------------------------------------------------------------------------
